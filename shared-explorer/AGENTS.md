# Explorer project instructions

Read `README.md` first. For project creation or model onboarding, load
`.agents/skills/explorer-project/SKILL.md`. All maintained documentation and
interface copy in this starter are English.

## Boundaries

- Configure projects in `project.config.json`. Put prepared models in
  `content/models/<id>/`. Add a model through the generic importer; do not add
  model-specific branches to the renderer.
- Preserve the approved floating interface, camera transitions, Ember default,
  engineering materials, crisp hidden-line rendering, flat highlights and tour
  controls. Adding content does not authorize redesigning these behaviors.
- `src/generated/` is generated by `npm run prepare:project`; do not hand-edit it.
- `src/explorer/` is the shared runtime. Model hierarchy, source attribution,
  curated appearance and tours belong to the model package.
- External hosts use the JSON controller through `embed-client.js`. Keep Three.js
  objects private and use one existing render loop and one animation clock.
- Do not introduce a backend, credentials, customer data or account integration
  into this public starter. A real application can implement its own host adapter.

## Validation and publication

Run `npm run verify` before release. Check the resulting `dist/` through an HTTP
server, including the repository subpath used by GitHub Pages. For a new model,
inspect engineering, linework, flat highlights, navigation, explode/restore and
any authored movement/tour at desktop and mobile sizes. Do not claim measured
performance on hardware you did not use.

Read `docs/deployment.md` before publishing. Public source and assets must be
redistributable. Follow the user's existing authorization for publishing; this
file grants no new authority to create accounts, invite collaborators or send
messages. Report deployed commit, tested routes, actual checks and limitations.
